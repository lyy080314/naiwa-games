# 玩转奶蛙 · 数据与接口约定 v1.1

> 对应实验 3「接口与数据实现」。本文件只约定主路径上最关键的一步：**管理员把一条外部游戏写进游戏集合，并在列表首项出现、刷新后仍在**。
> 约定形式为「页面提交 + 前端 Store 函数调用」，不涉及 HTTP 服务端。
> 变更本文件时同步修改第 6 行版本号，并在第 5 节追加记录。

## 1. 数据对象

### 1.1 Game（游戏条目）

存放位置：浏览器 `localStorage`，键名 `naiwa_games_v1`，值为 JSON 数组；只存管理员导入的条目，预设条目来自代码常量 `DEFAULT_GAMES`（只读，不入库）。

| 字段 | 类型 | 规则 | 用途 |
| --- | --- | --- | --- |
| `id` | string | 必填、唯一；系统生成，前缀 `c` + 毫秒时间戳 | 卡片定位、删除按钮 `data-del` |
| `name` | string | 必填；`trim()` 后非空；不限长 | 卡片标题 |
| `url` | string | 必填；唯一（按规范化后的值比较）；须为 `http/https` 且主机名合法 | 试玩 iframe 加载地址 |
| `intro` | string | 可选；≤ 60 字；缺省空串 | 卡片副标题 |
| `cover` | string | 可选；相对路径或 `data:image/jpeg` 的 dataURL | 卡片封面，缺省从 6 张内置图轮取 |
| `addedBy` | string | 系统写；取值 `admin` | 决定「管理员添加」角标与是否可删 |
| `createdAt` | number | 系统写；毫秒时间戳 | 创建时间留档，当前不参与排序 |

### 1.2 其它键（不属主路径）

| 键 | 位置 | 说明 |
| --- | --- | --- |
| `naiwa_admin_login` | sessionStorage | 管理态标记，`1` 表示已进入管理模式；关闭标签页即失效 |
| `naiwa_admin_pwd` | localStorage | 管理员口令覆盖值；未设置时回落到本地配置 |

## 2. 接口：提交一条导入

### 2.1 请求

- 调用方式：管理模式下打开「导入外部小游戏」弹窗 → 点「导入」，触发 `Admin.submitAdd()`，单条分支进入 `Admin.saveGame()`。
- 前置条件：`Admin.isLogin === true`；不满足时页面不渲染导入入口。
- 参数（取值为表单输入，均已 `trim()`）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `gameName` | string | 是 | 游戏名称 |
| `gameUrl` | string | 是 | 可省略 `https://`，系统自动补全 |
| `gameIntro` | string | 否 | ≤ 60 字 |
| `gameCover` | string / 文件 | 否 | 上传图片会压缩到 ≤ 320px 后转 dataURL |

### 2.2 成功

无返回值，以副作用表达成功，需同时满足三条：

1. `localStorage.naiwa_games_v1` 数组长度 +1，新条目追加到数组末尾；
2. 列表首项出现新卡片，带「管理员添加」角标，顶部计数 +1；
3. 弹窗关闭，页面顶部 toast 显示 `《名称》上架成功 🎉`。

写入的条目示例（示例数据）：

```json
{
  "id": "c1762300000000",
  "name": "奶蛙接口测试",
  "url": "https://example.com/play",
  "intro": "仅用于接口验收",
  "cover": "assets/img/frog-stand.jpg",
  "addedBy": "admin",
  "createdAt": 1762300000000
}
```

### 2.3 失败

失败时通过 `Admin.addErr(msg)` 把文案写入弹窗内 `#addErr`：弹窗不关闭、列表不新增、`localStorage` 不写入。当前实现以文案区分失败，无独立 `code` 字段；下表的 `code` 为本文档的索引编号。

| code | 触发条件 | 面向使用者的提示 |
| --- | --- | --- |
| `E_NAME_REQUIRED` | `gameName` 为空 | 请填写游戏名称 |
| `E_URL_REQUIRED` | `gameUrl` 为空 | 请填写游戏链接 |
| `E_URL_INVALID` | 规范化后仍不是合法 `http/https` 地址（含空格、无点号主机名等） | 链接格式不正确，请检查后重试 |
| `E_URL_DUPLICATE` | 规范化后的 `url` 与已有条目（含预设）重复 | 这个游戏已经在乐园上啦～ |
| `E_NO_PERM` | 未进入管理模式 | 导入入口不可见，无提示文案 |

## 3. 约束总结

- 校验顺序：名称 → 链接非空 → 链接格式 → 链接唯一。前一条不通过即返回，不继续。
- `url` 唯一性比较基于规范化结果，`example.com/play` 与 `https://example.com/play` 视为同一条；已有条目（含预设）的 `url` 同样先规范化再比较，因此预设里 `https://naiwa-gugupeng.pages.dev` 这类无尾斜杠地址也能命中。
- 存储顺序即导入先后（旧 → 新）；列表渲染时管理员条目倒序置顶，所以最近导入的一条总在首项，预设条目排在其后。
- 首项是否可见还取决于当前搜索词与分类筛选：验收时保持在「全部」且搜索框为空，否则新卡片可能被过滤掉。
- 写入是整表覆盖（`JSON.stringify` 整个数组），非增量更新。

## 4. 明确不做

- 不做服务端接口，不做跨设备共享（见报告第 5 节假实现）。
- 不做分页、排序、软删除。
